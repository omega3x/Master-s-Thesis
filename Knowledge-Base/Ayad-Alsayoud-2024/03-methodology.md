# Методология статьи

## Общая схема

```
Существующая BPM (XPDL/XML/XMI)
        ↓
Извлечение структуры (pools, lanes, activities, artifacts, связи)
        ↓
Структурированные данные (ArrayLists / CSV)
        ↓
Промпты к GPT-3.5 (zero-shot / few-shot / CoT)
        ↓
Список предложений (недостающие activities, artifacts)
        ↓
Моделировщик выбирает → обновляет модель
        ↓
Оценка: activity richness, artifact richness
```

## Шаг 1. Извлечение элементов модели

Из файла процесса (в статье и GitHub — **XPDL 2.2**) извлекаются:

| Элемент | Описание |
|---------|----------|
| **Pools** | Пулы (организационные контейнеры) |
| **Lanes** | Дорожки / роли внутри пула |
| **Activities** | Задачи, события, шлюзы (как activities в XPDL) |
| **Artifacts** | Документы и данные, связанные с активностями |

### Связи (relationships)

- Lane принадлежит Pool
- Activity принадлежит Lane (по координатам Y в их парсере)
- Artifact связан с Activity

### Реализация у авторов (GitHub)

Файл `Parsing_xml.py`:

1. Парсит `Medical2.xpdl`
2. Сохраняет `The_extracted_Activities.csv`
3. Сохраняет `The_extracted_Lanes.csv`
4. Сопоставляет lane ↔ activity → `The_extracted_Lanes_Activity.csv`

Логика сопоставления: activity попадает в lane, если её Y-координата внутри высоты lane.

## Шаг 2. Построение промптов

Для **каждого типа данных** создаётся отдельный промпт:

- промпт по lane;
- промпт по activity;
- промпт по artifact;
- промпт по связям.

Каждый промпт содержит **уже извлечённый контекст** из модели.

## Шаг 3. Три подхода к промптингу

Подробно — в `04-prompt-engineering-techniques.md`.

Кратко:

| Подход | Вход | Ожидание |
|--------|------|----------|
| Zero-shot | Только контекст модели | Список недостающих элементов |
| Few-shot | Контекст + примеры хороших дополнений | Более точные предложения |
| Chain-of-thought | Пошаговые инструкции | Рассуждение → затем предложения |

## Шаг 4. Обратная связь моделировщика

GPT-3.5 может **уточнять** предложения по feedback моделировщика.

Это не одноразовый запрос — итеративное улучшение.

## Шаг 5. Оценка качества

Две метрики из статьи:

### Activity richness

Насколько модель стала **богаче по активностям** после добавления предложений LLM.

### Artifact richness

Насколько модель стала **богаче по артефактам** (документы, данные).

Сравнивались разные комбинации:

- тип промпта (zero-shot / few-shot / CoT);
- конфигурация входных данных (что именно передаётся в промпт).

## Независимость от нотации

Метод **не привязан** к конкретному инструменту:

- XPDL (Bizagi) — основной в статье и GitHub;
- BPMN XML;
- XMI.

У нас: BPMN 2.0 (Camunda) → конвертация в XPDL (`tools/bpmn_to_xpdl.py`).

## Полуавтоматизация

| Делает ИИ | Делает человек |
|-----------|----------------|
| Анализирует текущую модель | Создаёт/утверждает исходную модель |
| Предлагает недостающие концепции | Выбирает, что добавить |
| Может уточнять по feedback | Проверяет domain correctness |
| — | Импортирует в Bizagi, симулирует |
