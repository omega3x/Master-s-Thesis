# О чём говорит статья

## Главная проблема

**Семантическое качество** бизнес-процессных моделей (BPM) часто страдает, потому что моделировщик **не владеет полным domain knowledge** предметной области.

Модель может быть визуально корректной (BPMN/XPDL открывается), но **неполной по смыслу**:

- пропущены важные активности;
- нет нужных артефактов (документов, данных);
- роли (lanes) не покрывают реальные обязанности.

## Главная идея статьи

Использовать **domain knowledge больших языковых моделей** (LLM), в частности **GPT-3.5 / ChatGPT**, чтобы **предлагать недостающие концепции** в уже существующей модели.

### Критически важно

Авторы **НЕ просят LLM нарисовать диаграмму**.

Они просят LLM:

> «Вот что уже есть в модели. Какие activities и artifacts отсутствуют?»

Моделировщик получает **список предложений**, выбирает подходящие и **сам** улучшает модель.

## Ключевые термины

| Термин | Значение в статье |
|--------|------------------|
| **Semantic quality** | Полнота и точность смысла модели (не только синтаксис XML) |
| **Domain knowledge** | Знание предметной области: роли, документы, типичные шаги |
| **Activity** | Задача или событие в процессе |
| **Artifact** | Данные, документы, объекты, связанные с активностями |
| **Prompt engineering** | Проектирование инструкций для LLM |
| **Semi-automation** | ИИ предлагает → человек решает |

## Что статья НЕ делает

- Не заменяет бизнес-аналитика полностью.
- Не привязана к одной нотации (работает с XML, XPDL, XMI).
- Не гарантирует идеальную модель без участия эксперта.
- Не фокусируется на layout/координатах диаграммы.

## Практический пример в статье

**Процесс Hospitalization (госпитализация)** — иллюстративный кейс.

Роли: Patient, Secretary, Doctor, Nurse.  
Модель уже содержит базовые шаги (регистрация, консультация, анализы).  
LLM предлагает, что ещё должно быть для **семантической полноты**.

## Оригинальность (value) по словам авторов

1. Опора на **domain knowledge ChatGPT-3.5**, а не только на знания моделировщика.
2. Три метода промптинга для извлечения точных предложений.
3. Выявление **missing concepts** → более полная BPM.
4. Улучшение semantic quality → более эффективный BPM в организации.
